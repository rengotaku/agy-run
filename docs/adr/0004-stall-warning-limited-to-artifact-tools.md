# ADR 0004: 空転の警告を成果物ツールに限る

## 背景

#37 では、画像生成が 429 で失敗し続けたとき（`generate_image` が 15 回連続・866 秒）を検出するため、同一ツールが閾値（既定 10 回）以上連続し画像成果物が 0 件の場合に `warnings` へ空転警告を記録する仕組みを導入した。

しかし、現行の判定はツールの種類を問わないため、テストやファイル参照を繰り返す通常のコーディング作業でも警告が出てしまっていた。

### 実測値（9/16 以降の 869 run）

`index.jsonl` の開始・終了時刻の範囲で run ごとの同一ツールの最大連続回数を集計した（`schedule` は除外）。

- 現行の閾値 10 で警告が出る run: 185 件（21%）
  - 内訳: `run_command` 144 件、`view_file` 等
  - 本来の対象である `generate_image` で 10 回以上連続: 0 件
- `run_command` の最大連続回数: 中央値 7、上位 10% の境目 15、最大 78
- `view_file` の最大連続回数: 中央値 6、上位 10% の境目 11、最大 65

上の 185 件は、画像成果物が 0 件という条件を適用した件数。次の連続回数と結果の関係は、その条件を適用せず、最大連続回数が 10 以上かどうかだけで分けた（ログの会話 ID で `index.jsonl` と結合、700 run）。

- 10 回以上連続した run: 151 件中、print timeout 26 件（17%）、失敗（exit が 0 以外、または error あり）36 件（24%）
- 10 回未満の run: 549 件中、print timeout 66 件（12%）、失敗 95 件（17%）

10 回以上連続した run とそうでない run で、失敗率の差は小さかった（17% 対 12%、24% 対 17%）。最大連続回数は `run_command` で中央値 7 から最大 78 まで、`view_file` で中央値 6 から最大 65 まで幅広く、閾値で二分する根拠は見つからなかった。現状の警告は、コーディング作業の通常の呼び出しで多発していて、警告として機能していない。

## 決定

**空転の警告を、成果物を作るツール（`convlog.ArtifactTools`、現状は `generate_image` のみ）に限る。**

1. **成果物ツールのみを警告対象とする**: 成果物ツールではないツール（`run_command`、`view_file` 等）が連続しても警告は出さない。
2. **非成果物ツールは連続を途切れさせる**: 成果物ツールではないツールの呼び出しが入った場合、それまでの連続を途切れさせる（`schedule` 以外の別ツールを挟むと連続が途切れる既存の扱いと同様）。途切れた時点でそれまでの連続を確定し、カウントを初期状態に戻す。非成果物ツール自体の呼び出しは連続の計上に加えない。
3. **`schedule` の扱いは維持**: 待機ツール（`schedule`）は従来どおり読み飛ばし、連続を途切れさせない。
4. **閾値と成果物条件の維持**: 閾値（`AGY_RUN_TOOL_REPEAT_LIMIT`、既定 10）および画像成果物が 0 件という条件は変更しない。
5. **警告文言と実行継続**: 警告の文言は変更しない。空転が検出されても実行は中断せず記録のみとする（#44 の自動打ち切りは別判断）。

## 検討して捨てた案

- **閾値を上げる**: 連続回数が中央値 7 から最大 78 まで幅広く、閾値で二分する根拠が見つからず、「何回以上が空転か」の境界を引けないため却下。
- **ツールごとに閾値を変える**: ツールごとに連続回数を変えても、通常作業との境界を客観的に引く根拠が存在しないため却下。
- **警告をやめて記録だけにする**: #44（空転時の自動打ち切り）の是非を判断するためのデータは別途必要であり、本来の目的である成果物生成ループの検出機能そのものは警告として維持すべきであるため却下。

## 変えてよい前提

- 成果物ツールの一覧（`convlog.ArtifactTools`）へのツールの追加（将来別の成果物生成ツールが増えた場合）。
- 閾値（`AGY_RUN_TOOL_REPEAT_LIMIT`、既定 10）の調整。

## 壊すと危ない前提

- **`schedule` を連続の計上に含めないこと**: `schedule` を挟んでも成果物ツールの連続が途切れないようにすること（既存のテスト D1 は、`generate_image` の間に `schedule` が挟まる形を想定している。途切れさせると、そうした形のループを検知できなくなる）。
- **判定不能のときに警告を出さないこと**: transcript が存在しない・読めない・壊れている場合にクラッシュさせず警告も出さないこと。
